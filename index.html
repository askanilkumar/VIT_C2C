Meet CampusCart 🛒

Two students build a campus marketplace app.

It works perfectly on their laptops. They launch on a Friday with a flash-sale email to 2,000 students.

What could go wrong?

Launch night, 9 PM

8:55 PM · Flash-sale email goes out 📧
9:02 PM · Pages load slowly
9:10 PM · Payments start failing
9:20 PM · Database disk is 100% full
9:45 PM · Site is down. Customers leave bad reviews.
2:00 AM · Someone finally fixes it. Nobody was watching.

Who was responsible for keeping it running? → Ops

What is "Ops"?

Operations = everything needed to keep software running for real users.

🚚 Deploy

Get new versions live safely

👀 Monitor

Know when something is wrong

📈 Scale

Handle 20 or 20,000 users

🔒 Secure

Patch, protect, control access

🛠 Fix

Respond to incidents fast

💰 Control cost

Pay only for what you need

Why Ops matters

⏱ Availability

Every minute offline is lost orders and lost work.

🤝 Trust

Users forgive a missing feature. Rarely a lost payment.

🛡 Security

One misconfigured server can expose everything.

💸 Cost

A forgotten cloud resource quietly burns money every hour.

Development vs Deployment

🧑‍💻 Development

  • Build features
  • Runs on your laptop
  • Tools: IDE, Git
  • Question: "Does it work?"

🚀 Deployment

  • Run it for real users
  • Runs on servers / cloud
  • Tools: pipelines, containers, cloud
  • Question: "Does it work for everyone, always, safely?"

"But it works on my machine!" 🤷

💻 Your laptop

  • Python 3.11
  • Windows
  • Test database, no password
  • 1 user (you)

☁ The server

  • Python 3.8
  • Linux
  • Real database, secrets, firewall
  • 2,000 users at once

Same code. Different environment. Different result.

What is DevOps?

🤝 A culture

Dev and Ops share goals and responsibility.

⚙ A set of practices

Automation, small releases, fast feedback.

🧰 Supported by tools

Git, CI/CD, containers, cloud, monitoring.

Not just a tool. Not just a job title. Goal: ship small changes quickly, safely, repeatedly.

Why it is significant: speed and stability

Research from DORA (DevOps Research and Assessment) tracks four classic measures:

Deploy frequency

How often you ship

Lead time

Commit to production

Change failure rate

How often a release breaks things

Time to restore

How fast you recover

The finding that surprised people: high performers are faster and more stable. Speed and safety are not a trade-off.

The 8 phases: a loop that never stops ♾

Left loop = build side (Dev) · Right loop = run side (Ops) · Monitor feeds the next Plan

CI vs CD vs CD: three terms, one idea

TermMeaning
Continuous IntegrationMerge often. Every commit is built and tested automatically.
Continuous DeliveryEvery passing build is ready to release. A human approves the button.
Continuous DeploymentEvery passing build goes to production automatically.

This file is a DevOps pipeline 🔧

name: ci
on: [push]
jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: pip install -r requirements.txt
      - run: pytest

You can write and run this tonight, for free, on GitHub.

→
AI groups them into 1 incident
→
Suggests the probable cause
→
Runs a runbook or proposes a fix

Less noise. Faster diagnosis. Humans still decide.

The self-healing pipeline 🩹

Pipeline fails ❌
→
Agent reads the logs
→
Finds the cause
→
Opens a fix (pull request)
→
Tests pass → human approves ✅

Agents reach your tools (Git, CI, cloud) through standard connectors such as MCP. Power is only useful with guardrails: least privilege, approvals, audit trail.

New "Ops" born from AI

MLOps

Train, deploy, monitor and retrain ML models

LLMOps

Prompts, evaluations, guardrails, cost per request

AgentOps

Observe and govern AI agents running in production

Same DevOps ideas (automate, monitor, improve) applied to a new kind of software.

What AI does not change ⚠

  • AI can hallucinate configs, commands and package names.
  • AI can leak secrets or grant over-broad permissions.
  • You still need to read, test and understand what it produced.
  • When production breaks, a human is accountable.

Rule of thumb: AI proposes. You review, test, then apply.
